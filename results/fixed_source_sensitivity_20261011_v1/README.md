# RQ3.3: attribution-target sensitivity

This is the fixed-metric sensitivity analysis on Oxford-IIIT Pet and CUB-200-2011 reported in RQ3.3. It uses the original runs' holdout source images, which belong to the two **metric-development datasets**, not four new independent verification datasets. No components, fusion weights, or thresholds were retuned.

The source map targets the source prediction in both conventions. The follow-up map targets either its own prediction (primary convention) or the source prediction (fixed-source convention). Both are evaluated against actual prediction-label inconsistency, not independently verified classification error.

| Attribution target | Oxford-IIIT Pet AUROC | Oxford-IIIT Pet AP | CUB-200-2011 AUROC | CUB-200-2011 AP |
|---|---:|---:|---:|---:|
| Own predicted class | 0.8953 | 0.6888 | 0.8067 | 0.8684 |
| Fixed source-predicted class | 0.7973 | 0.5095 | 0.7658 | 0.8484 |

These comparisons use 2,979 matched Pet pairs and 2,887 matched CUB pairs. Two invalid fixed-source CUB maps are excluded from both conventions; the primary own-class result on the original 2,889 valid pairs remains AUROC 0.8066. Prediction-consistent pairs have identical targets and identical scores under both conventions.

## Files

- `summary.json`: full coverage, point estimates, 1,000 source-image-cluster bootstrap results, per-background diagnostics, input hashes, and extraction checks.
- `pets_v1_summary.json` and `cub_v1_summary.json`: the corresponding per-dataset results.
- `pets_v1_matched_scores.npz` and `cub_v1_matched_scores.npz`: aligned, non-object NumPy arrays, with one row per matched source/background pair. `source_ids` and `backgrounds` identify pairs; `inconsistent` is 1 when the label changes. `own_JSD`, `own_NCD`, `own_HRCAM`, `fixed_JSD`, `fixed_NCD`, and `fixed_HRCAM` contain the derived scores.
- `REPORT.md`: archived report generated by the original analysis. Its statements that the manuscript/repository were unchanged describe the analysis-time state, before this publication.

All diagnostic component results are retained, including the finding that JSD alone exceeds H-RCAM under fixed-source targeting. The primary own-class ranking must not be generalized to that convention. This sensitivity check does not rerank all nine individual candidate measures.

## Verify the published score-level results

With NumPy and scikit-learn installed, from the repository root:

```bash
python verify_fixed_source_release.py
```

This requires no images, heatmaps, checkpoints, or GPU. It verifies the original script hash, matched coverage, harmonic score calculation, all component AUROC/AP point estimates, and identical scores for prediction-consistent pairs. It does not rerun extraction or bootstrap intervals.

## Reproduce the full analysis

See the root-level `FIXED_SOURCE_SENSITIVITY_PROTOCOL.md`. Regenerate the original `runs/pets_v1/` and `runs/cub_v1/` extraction artifacts using the source datasets and existing experiment scripts. The full analysis requires the original classifier checkpoints, prepared image/mask arrays, split manifests, pair records, and cached heatmaps containing both target conventions. These large files are not redistributed here.

The archived analysis script verifies the original classifier and pair-record SHA-256 hashes before proceeding. A newly trained checkpoint may not be byte-identical across environments; a hash mismatch is a provenance-check failure, not a reason to silently bypass the check and claim an exact reproduction.

The original analysis used Linux, CUDA, and CPU affinity 24-31. On a machine supporting that affinity, with the original artifacts and an unused output directory:

```bash
python fixed_source_sensitivity.py --self-test
taskset -c 24-31 python fixed_source_sensitivity.py --root . --output results/rq33_reproduction --bootstrap 1000
```

The CPU-affinity guard is intentionally retained in the exact archived script. Its SHA-256 is recorded in `summary.json`; the full run verifies extraction on 16 sources/48 pairs per dataset and recomputes the components for all cached pairs before inference. A fresh-environment, end-to-end reproduction has not been completed; the score-level verification above provides a lightweight check of the released results.
